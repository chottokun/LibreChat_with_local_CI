# テスト戦略・TDD

## 📝 開発サイクル（TDD）

1. **Red**：要件を満たす失敗するテストを最初に作成する
2. **Green**：テストを通すための最小限の実装を行う
3. **Test**：正常系・異常系・境界値などのテストを追加する

   * 実データを利用する場合は、個人情報・認証情報などを匿名化し、機密情報はコミットしない
4. **Refactor**：コードを整理し、重複や可読性を改善する
5. **Document**：Google スタイルの Docstring を追加し、必要に応じて `README.md` や `CHANGELOG.md` を更新する

## 必須のテスト検証項目

以下の重要領域を変更する際は、必ず `tests/` 内に該当するテストケースが存在、または合格することを確認すること：

* **多言語実行検証**: Python、Bash、R が想定通りに安全に動作すること。
* **境界セキュリティ検証**: パストラバーサル（`../../` 等の悪意ある入力）によるホストシステムへの侵入が完全に遮断されていること。
* **高負荷並行セッション制御**: 多数のセッション（コンテナ）が並列で動いた際、デッドロックや作成上限突破を防ぎ、スレッドセーフにファイルマッピングとクリーンアップが行われること。
* **セッションID解決**: NanoID ↔ 内部 UUID の双方向マッピングおよびフォールバックロジックが正しく機能すること。
* **認証フォールバック**: `X-API-Key` ヘッダー、`Authorization: Bearer` トークン、クエリパラメータの全認証経路が動作すること。
